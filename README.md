# 价值投资智能分析模型 · 云端版

把原桌面版（Tkinter + Selenium）的《价值投资分析模型V1.4-3（扩展）1.0（修复版）》
改造成 **可在 GitHub + Streamlit Community Cloud 上部署、手机浏览器直接使用** 的前后端程序。

---

## 一、功能对照（哪些保留、哪些改造）

| 原桌面版模块 | 云端版 | 实现方式 |
|---|---|---|
| 1. 海选公司（问财 + Selenium） | ✅ **保留功能，换数据源** | AkShare 全市场清单 + 年度财务指标（净资产收益率/毛利率/现金含量…）按“连续 N 年”过滤，产出同名四张表 |
| 2. 下载年报（巨潮 PDF） | ❌ **按要求取消** | —— |
| 3. 年报提取（PDF 解析） | ✅ **改为「年报数据搜索汇总」** | AkShare 新浪财报表（三大表）+ 东财/同花顺分红 + 员工薪酬，**产出与原《年报提取表》《统一整合输出》《公司属性表》《同行排列表》表结构完全一致** |
| 4. 造假排雷（18 项） | ✅ **原样保留** | 逐字移植原判断逻辑与阈值，已在真实数据上做 AST 级等价校验（129 项断言全过） |
| 5. 16 维度同行对比 | ✅ **原样保留** | 逐字移植，6075 个单元格与原程序输出**零差异** |
| 6. AI 文本分析 | ❌ **按要求取消** | —— |
| 7. 企业 AI 深度分析 | ✅ **保留** | 本地资料从 PDF 改为本项目汇总的表格（提示词/截断长度/温度与原版一致） |
| 8. 好价估值 | ✅ **保留功能，换数据源** | 大盘 PE 用 AkShare（乐咕乐股），个股现价/PE(TTM) 用腾讯·新浪行情，**动态股息率=严格 TTM**（近12个月已实施分红累加÷现价）；`judge_stock` 判断规则逐字保留 |

> 说明：原“下载年报”在云端不可行（无浏览器、磁盘不持久、PDF 体积大），
> 因此按你的要求取消；其数据职责由「年报数据搜索汇总」直接以结构化数据完成。

## 四、部署到 Streamlit Community Cloud（手机可访问）

1. 把 `价值投资网络程序/` 里的**全部内容**推送到 GitHub 仓库（建议直接作为仓库根）。
   必须一起上传的：`app.py`、`core/`、`server/`、`webapp/`、`requirements.txt`、`packages.txt`、`.streamlit/`。
2. 打开 <https://share.streamlit.io> → **New app** → 选择该仓库与分支。
3. **Main file path** 填：`app.py`（仓库根入口）**或** `webapp/app.py` —— 两者都可以，入口会自动定位 `core/`。
4. （可选）在 **Advanced settings → Secrets** 里配置，避免把 Key 写进代码：
   ```toml
   [ai]
   api_key = "sk-你的DeepSeekKey"
   base_url = "https://api.deepseek.com/v1"
   model = "deepseek-chat"
   ```
5. Deploy。部署完成后会得到一个 `https://<app>.streamlit.app` 地址，**手机浏览器直接打开即可使用**。

### 仓库摆放说明（已实测 5 种组合均可运行）

入口通过 `bootstrap.py` / 内联引导**向上逐级查找含 `core/pipeline.py` 的目录**，
因此下面任意一种摆放都能正常工作：

| 摆放方式 | Main file path |
|---|---|
| 全部内容铺在仓库根 | `app.py` 或 `webapp/app.py` |
| 套一层 `价值投资网络程序/` | `价值投资网络程序/app.py` 或 `价值投资网络程序/webapp/app.py` |
| 只有 `webapp/`（无根 `app.py`） | `webapp/app.py` |

> ⚠️ 常见报错 `ModuleNotFoundError: No module named 'core'` 的原因：
> 只上传了 `app.py` 而**没有一起上传 `core/` 文件夹**，或 `core/` 没有和入口放在同一层。
> 现在这种情况不会再抛裸异常，而是显示一个**中文诊断页**，列出它查找过的每个目录及其内容，
> 便于一眼看出缺了什么。

### 部署报错排查（按报错原文对照）

| Cloud 上的报错 | 原因 | 处理 |
|---|---|---|
| `You do not have access to this app or it does not exist` | 不是代码问题。①应用在你的个人工作区，需用**应用所属账号**登录后访问；②网址不对（务必用 share.streamlit.io 应用页显示的 URL）；③还没部署成功 | 登录 share.streamlit.io → My apps → 进入应用；再在 Manage app → Settings 里把 Viewer access 设为公开，手机即可免登录打开 |
| `ModuleNotFoundError: No module named 'core'` | 仓库里缺 `core/` 文件夹 | 上传 `core/`（13 个 .py）；入口已内置中文诊断页，会列出缺失项 |
| `❗️ installer returned a non-zero exit code` + `Error during processing dependencies!` | **`packages.txt` 里有不存在的 apt 包名**，导致 apt 整体失败（Python 依赖本身没问题也会失败） | 本仓库已修正：移除了 Debian 不存在的 `libxslt1-dev`，只保留 `build-essential / python3-dev / zlib1g-dev` |
| pip 解析或安装某个包失败 | 可选依赖（`duckduckgo-search`、`ddgs`、`tushare`）会拉入 `primp` 等编译型/大体积依赖 | 本仓库已把可选依赖移到 `requirements-extras.txt`，默认不装；需要时再复制到 `requirements.txt` |

**依赖分层说明**

- `requirements.txt`：**核心必需**，已全部加版本上限（`streamlit>=1.36,<2`、`pandas>=2.2,<3`、
  `numpy>=1.26,<3`、`akshare>=1.14`、`openai>=1.30,<2` 等）。其中 `openai` 必须锁在 **1.x**：
  2.x/3.x 改用 `httpx`/`httpx2` 客户端，容易与 Streamlit 的 httpx 生态冲突。
- `requirements-extras.txt`：**可选增强**（baostock / tushare / duckduckgo-search / ddgs）。
  缺失时代码自动降级：没有 baostock/tushare 就只用 AkShare；没有 ddgs 就跳过联网检索。
  前端侧边栏会显示 **数据源可用性**（`✅ AkShare(主) · ⬜ Baostock(备) · ⬜ TuShare(备)`）。

> 部署注意事项
> - Python 版本建议 **3.11 / 3.12**。
> - 云端磁盘**重启后会清空**：所有产物请用「📦 产物」页的 **打包下载 zip** 及时保存。
> - 免费额度下 CPU/内存有限，建议把「海选候选池大小」控制在 100~300。
> - 若只跑前端，可从 `requirements.txt` 注释掉 `fastapi/uvicorn` 以加快安装。

### 运行中的暂停 / 停止

任务运行时会显示 **⏸️ 暂停** 与 **⏹️ 停止** 两个按钮（在进度条下方）：

| 按钮 | 行为 |
|---|---|
| ⏸️ 暂停 / ▶️ 继续 | **协作式**暂停：当前这一步（例如一次网络请求）跑完后挂起，状态变为「已暂停」；点“继续运行”恢复。不会丢数据，也不会打断正在写文件的操作 |
| ⏹️ 停止 | 立即请求中止：当前阶段在下一个检查点抛出中断并结束，**已经生成的产物文件会保留**；后续阶段不再执行 |

> 为什么是"检查点"而不是真挂起线程：所有耗时都在同步网络请求里，Python 无法安全地打断；
> 在循环边界检查是最稳、且不会破坏数据一致性的做法。因此按下后可能需要等当前这一步完成
> （通常几秒，最长约一次网络请求的超时时间）。
> 远程 API 模式对应 `POST /api/jobs/{id}/pause?paused=true|false` 与 `POST /api/jobs/{id}/cancel`。

### 海选条件设置（🎯 海选 页）

「🎯 海选」页有一块 **⚙️ 筛选条件设置** 面板，逐条可调（填 **0 表示不启用**该项）：

| 控件 | 说明 | 出厂默认 |
|---|---|---|
| 连续年数 | 最近 N 个完整会计年度**每年**都要满足下面的门槛 | 5 年 |
| ① 加权净资产收益率(ROE) > | 取“加权净资产收益率”，缺失回退“净资产收益率” | 20% |
| ② 销售毛利率 > | 按利润表口径 (营业收入−营业成本)/营业收入 | 40% |
| ③ 净利润现金含量 > | 经营现金净流量÷净利润；>100% 表示利润有现金支撑 | 100% |
| ④ 上市时间 > | **精确上市日期**（巨潮公司概况，逐只带缓存）计算已上市年数 | 3 年 |
| ⑤ 总市值 > | 亿元；在候选池阶段过滤 | 不限 |
| ⑥ 市盈率(TTM) < | 启用后逐只取实时 PE | 不限 |
| 剔除北交所 / 剔除金融股 / 剔除 ST | 勾选即生效 | 均勾选 |
| 候选池大小 | 按总市值降序取前 N 只参与筛选（越大越全越慢） | 200 |

- **条件模板**：下拉可选「默认A股多条件 / 优势大市值 / 高股息低估值 / 标准条件(原程序)」，
  套用后仍可逐条微调；选“自定义”则保持当前值。
- **💾 保存为我的默认条件**：把当前设置写入配置，下次进入自动带出。
- **当前生效条件**：面板下方实时显示拼好的条件文本，避免“设了却没生效”的误会。
- **未通过原因**：跑完后展开“候选明细”，每家公司都有 `未通过原因` 列（如
  `ROE未连续5年≥20`、`毛利率未连续5年≥40`），便于核对是数据缺失还是真的不达标。
- **🛠 高级：文字条件**：兼容原桌面版问财写法（如 `连续3年股息率>5%`），
  比较符支持 `> ＞ 大于 ≥ >= / < ＜ 小于 ≤ <=`；填了文字条件时以它为准。
  面板未覆盖的条件片段会在日志里以“未能解析的条件片段（已忽略）”列出，不会静默丢弃。

> 实现说明：面板产出的是**结构化条件字典**，经 `core.screening.normalize_conditions()`
> 规整后直接进入筛选引擎；文字条件则走 `core.screening.parse_query()` 解析成同一结构。
> 两条路径最终共用同一套判定，端口径一致。
>
> **④ 上市时间**采用精确口径：`ak.stock_profile_cninfo` 取“上市日期”，
> 按 `整年数 + 当年已过天数/365` 算出 2 位小数的上市年数（例：东鹏饮料 2021-05-27 → 5.37 年）。
> 为规避一个已知的崩溃点，该接口**必须串行调用**：
> `stock_profile_cninfo` 内部用 py_mini_racer(V8) 解析 JS，该引擎**不是线程安全的**，
> 并发调用会让进程在 `mini_racer.dll` 内直接崩溃（Python 层无法捕获，实测 6 线程取 6 只即触发）。
> 因此实现为**串行 + 磁盘缓存 + 时间预算（240s）**：单只约 0.3 秒，首次约 2~3 分钟，
> 之后全部命中缓存（0.00 秒）。取不到上市日期的公司按“保守剔除”处理并在日志中计数，
> 不会误选入池。

## 六、数据来源（全部免费，无需 token）

**多源容错**：`core/datasource.py` 统一封装 AkShare（主）→ Baostock（备）→ TuShare（备，需 token），
缺字段/限流时自动换源补齐；三个源都可选，未安装的包或未配置 token 的来源**自动跳过**，不会报错。

| 用途 | 主源 | 备用源 |
|---|---|---|
| A股全市场清单 | `ak.stock_info_a_code_name` / `ak.stock_zh_a_spot` | Baostock `query_all_stock` |
| 行业分类 | 东方财富 F10（datacenter） | 巨潮 `stock_industry_change_cninfo` |
| 三大财务报表 | `ak.stock_financial_report_sina` | Baostock `query_profit/balance/cashflow_data` |
| 分红送转 | `ak.stock_history_dividend_detail`（同花顺）+ `ak.stock_fhps_detail_em`（东财） | TuShare `dividend` |
| 年度财务指标（海选用） | `ak.stock_financial_analysis_indicator` | Baostock `query_profit_data`（roeAvg/gpMargin）→ TuShare `fina_indicator` |
| 毛利率（新浪字段常为空） | 利润表口径计算 (营业收入−营业成本)/营业收入 | Baostock `gpMargin` → TuShare `grossprofit_margin` |
| 高管/公司概况 | `ak.stock_management_change_ths` / `ak.stock_profile_cninfo` | —— |
| 个股现价 / PE(TTM) | 腾讯行情 `qt.gtimg.cn` | 新浪行情 `hq.sinajs.cn` |
| 大盘 PE / 国债 / 美联储 | `ak.stock_a_ttm_lyr`、`ak.stock_index_pe_lg`、`ak.bond_zh_us_rate`、`ak.macro_bank_usa_interest_rate` | 中证指数 `stock_zh_index_value_csindex` |

> 口径说明（已实测校正）：新浪的“经营现金净流量与净利润的比率”返回的是**倍数**（0.6056），
> 而选股条件写的是百分数（>100），故代码里统一 **×100 归一**为百分数后再比较。
> 毛利率因新浪字段常年为空，改用**利润表口径**计算，并由 Baostock/TuShare 兜底。

## 七、与原桌面版的关键契约（改动时务必遵守）

1. 《公司属性表》文件名含“公司属性表”，列：`目标股票/股票简称/一级行业/二级行业/三级行业/完整行业路径`。
2. 单年《年报提取表》：`{简称}（{代码}）{年份}年度年报提取表.xlsx`，11 张 sheet 同名同义。
3. 《统一整合输出》：`统一整合输出_{简称}({代码})_{起}-{止}.xlsx`，5 张 sheet：
   `员工情况(PDF提取)/分红情况/合并资产负债表/合并利润表/合并现金流量表`；
   三大表列 = `['项目','20231231','20241231',...]`；分红表列 = `['股票代码','年份','同花顺现金分红总额(元)','归属于母公司所有者的净利润(元)','分红率']`。
4. 行业目录名：`{代表公司}_行业_{行业名}`。
5. 下游按文件名正则 `(.*?)[(（](\d{6})[)）]` 取代码。

> 云端版把《统一整合输出》的**表头放在第 1 行**（原版第 1 行是合并标题），
> 解析侧已同时兼容两种版式。

## 八、已知限制

- **员工人数**：免费公开接口不提供，改为提供“支付给职工以及为职工支付的现金”（现金流量表）。
  依赖员工人数的排雷第 1 条在无数据时不触发（与原程序“缺失即跳过”的行为一致）。
- **恒生指数 PE / 标普500 PE**：相应免费接口在部分网络下不可用，取不到时报告显示 `N/A`；
  此时港美股的“判断结果”会显示“宏观数据不足”（A 股不受影响）。
- **东方财富行业接口偶发超时**：`datacenter-web.eastmoney.com` 会间歇性超时。已做三层防护：
  ① 单次超时 15s→**8s**、重试 2 次→**1 次**（最坏耗时从 ~40s 降到 ~16s）；
  ② 连续失败 3 次后**本轮自动熔断**，改用更快的巨潮行业分类（约 0.3s/只）；
  ③ 失败结果写入**短期负缓存**，同一只股票本轮不再重复请求。
  失败时该公司归入“默认行业”，不影响其它公司与后续阶段。
- **大盘 PE 口径**：桌面版抓乐咕乐股“深圳A股 PE”，云端改用
  `ak.stock_a_ttm_lyr` 的 A 股滚动市盈率中位数（报告与日志会写明口径）。
- 免费接口偶发限流/超时：所有网络调用都带 3 次重试 + 退避，个别失败只记日志不中断。

## 九、验证情况（真实数据）

**全链路实测**（候选池 30 只 → 条件「连续3年加权roe>8，连续3年毛利率>20，剔除北交所，非金融股」）：
